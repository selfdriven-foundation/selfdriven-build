the idea

Trust needs a verifiable floor.

The selfdriven.computer model makes every agent action sequenced, signed and witnessed, six layers deep. Each of those guarantees ends up executing on a chip, and a closed chip is the one part that still asks for blind trust. Open Silicon is Layer 00: the floor you can check instead of assume.

  • 01 · KeysHardware holds the rootSigning and pre-rotation keys are only as safe as the silicon that stores and uses them.
  • 02 · SequenceThe clock runs on a chipLayer 01's sequence is computed by a processor. Open designs show what it is meant to do.
  • 03 · RuntimeExecution you can auditStateless runtimes are disposable by design. On open silicon, the hardware under them can be audited too.
  • 04 · AttestationIdentity from the device upOpen roots of trust give device identity and measured boot, the same verify-don't-trust move as a key event log.
  • 06Ecosystem applicationsDomain services and A2A
  • 05Shared trust layerWitness network and KEL sync
  • 04Agent runtimeDelegated AID execution
  • 03Policy and verificationACDC credential enforcement
  • 02Instruction primitivesFive atomic operations
  • 01Clock cycleSequenced, verifiable time
  • 00SiliconThe chip it all runs onthis build

the flow

From an idea to a die in your hand.

Six steps, the same on every path. Tiny Tapeout automates the middle ones for you; on your own die you run them yourself. Select a step.

Step 01 · Design

Write the logic

Start from a template. In Wokwi you wire gates in the browser; in Verilog you write one top module whose name starts with tt_um_. Every design gets the same frame: 8 inputs, 8 outputs, 8 bidirectional pins, a clock and a reset.

WokwiVeriloginfo.yaml
module tt_um_yourname_padlock (
  input  wire [7:0] ui_in,    // 8 inputs
  output wire [7:0] uo_out,   // 8 outputs
  input  wire [7:0] uio_in,   // 8 bidirectional
  output wire [7:0] uio_out,
  output wire [7:0] uio_oe,   // 1 = output
  input  wire       ena, clk, rst_n
);
how this build runs

One chip. All four modes.

Constructive leads, but this is the slowest build on the bench, and it needs the other three to get through.

  1. 01 · Curious

    Plan it

    Learn what a gate, a flip-flop and a clock actually do. Open a past shuttle's chip map and pick a design to understand.

  2. 02 · Constructive

    Build it

    Design, test, harden, submit. Shuttles close on a date, so a rough design that passes is the one that gets made.

  3. 03 · Caring

    Tend it

    Write down the pinout and how to test it. Keep the repo open so the next builder can fork your work instead of starting over.

  4. 04 · Chill

    Live with it

    Then wait months for the fab. The wait is part of it. Start the next idea, and when the board arrives, wake the chip up.

verify a chip

Not making one? Check one.

The other half of Open Silicon needs no shuttle. Open designs are there to be read, so pick one and follow the evidence.

Read a root of trust

OpenTitan is the first open-source silicon root of trust in production, shipping in Chromebooks since 2026. Its RTL and docs are public. Start with the Earl Grey chip and the Ibex RISC-V core inside it.

opentitan.org

Look inside a shared die

Every Tiny Tapeout shuttle publishes a chip map of the designs on it. Pick one, open its repo, and trace it from Verilog to the layout on the die.

The chips

Follow the chain up

Caliptra takes the same open root-of-trust idea into datacentre chips, developed by Google, AMD, Microsoft, Marvell and NVIDIA under the CHIPS Alliance.

Caliptra

It is the same move as reading a key event log: don't take the claim, replay the evidence. A KEL lets you check an identity from inception. An open chip lets you check the hardware from its source. Read the full case on selfdriven.computer.
